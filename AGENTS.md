# Nimbus project rules

- Commit as `Uttamb7`; use `Uttam Bhattarai` for human attribution.
- Keep issues specific, proportionally sized, and free of repeated boilerplate.
- Documentation is exception-based. Update only key architecture, operations, security, or user-facing information that materially changes.
- Do not update documentation for every issue. Use `No documentation change required` when a ticket has no essential documentation impact.
- Never claim unverified infrastructure, tests, metrics, or production behavior.
